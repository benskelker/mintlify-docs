This topic describes how to manage certificates for Security Information and Event Management (SIEM) integrations in Threat Detection and Response using the SIEM integrations page.

Overview
----------------------

The SIEM integrations page provides a single interface for creating, viewing, renaming, and revoking certificates used to authenticate integrations between Threat Detection and Response and supported SIEM systems - Splunk and IBM QRadar.

Integrations use mutual TLS (mTLS) certificates to securely forward logon event data for detection and analysis of credential theft, unmanaged privileged account activity, and other suspicious behavior.

Integration setup
-------------------------------

1.   Sign in to the Administration space.

2.   In the left pane, go to My environment, then select Integrations &gt; Import data from SIEM.

3.   Click Integrate with Splunk or Integrate with QRadar. This action launches the integration configuration process and automatically generates the certificates required for secure data exchange.

Certificate creation and display
----------------------------------------------

Each certificate generated by Threat Detection and Response is automatically named and stored in the certificate list. You can rename a certificate later for easier identification.

After creation, the following information appears for each certificate:

*   Certificate name - A unique, system-generated identifier that can be renamed.
*   Issued on - The creation date of the certificate.
*   Last message received - The timestamp of the last data transmission from the SIEM application.
*   Status - Displays whether the certificate is active, expired, or revoked.

The Last message received field reflects real-time activity, showing when the SIEM application last communicated with Threat Detection and Response.

Rename a certificate
----------------------------------

To make it easier to identify specific integrations, you can rename certificates at any time.

1.   Locate the certificate in the SIEM integrations page.

2.   Click the certificate name and enter a new name.

3.   Click Save.

Only the certificate name can be edited. Other certificate properties are read-only to preserve security integrity.

Revoke a certificate
----------------------------------

If a certificate becomes compromised, outdated, or no longer needed, you can revoke it to prevent further communication between the SIEM and Threat Detection and Response.

1.   Locate the certificate in the SIEM integrations page.

2.   Click Revoke. The certificate status changes to Revoked.

Once revoked, a certificate cannot be reactivated. To restore communication, create a new certificate and reconfigure the corresponding SIEM integration.

Monitor certificate health
----------------------------------------

Use the Last message received field to monitor data activity. A recent timestamp confirms successful event forwarding between the SIEM and Threat Detection and Response.

If a certificate shows no recent activity, verify that the integration is active or generate a new certificate if required.
