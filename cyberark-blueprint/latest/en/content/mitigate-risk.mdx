Now that you understand how bad actors compromise identity to execute their endgame and what you should strive for to stop them, you can take a deeper dive into the specific cybersecurity controls that you can implement to mitigate the risks of identity attacks. This topic outlines a variety of identity-related cybersecurity controls according to the guiding principles they support.

If you’re reading this section and you find yourself asking, “Why are there so many controls?” the answer is simple – identity security isn’t a one-size-fits-all approach. Modern enterprises have a seemingly infinite number of human and non-human identities that access technologies and resources, and which run the spectrum of authentication and authorization methods. As such, it’s important to understand which identity security controls can be used to mitigate the risks in any given scenario.

Prevent identity compromise
-----------------------------------------

*   Single sign-on (SSO): Single sign-on is a method of authentication that enables an organization to have their human users leverage a single set of credentials to access many different resources (service providers) via an identity provider (IdP). SSO gives organizations the ability to enforce additional security controls, as it serves as an entryway into other resources and can support passwordless authentication. This helps mitigate the risk of credential theft by cutting down on the need to have many credentials or by removing the need to use a credential entirely.

*   Adaptive multifactor authentication (AMFA/MFA): Adaptive multifactor authentication is an intelligent way of deciding when to prompt human users for a secondary factor to validate or prove they are who they claim to be. This helps mitigate the risk of credential theft by requiring a malicious actor to not only steal credentials, but also to compromise the additional factors a user is required to provide. This is a common defense in depth, or layering approach, to security.

*   Complex passwords/secrets: Complex passwords (secrets, credentials, and so on) for systems that require password-based access are an important part of preventing credential theft. Weak passwords can be easily brute forced, resulting in the password being “stolen” by guessing. Having complex password policy requirements (predominantly for systems that don’t support MFA or other authentication methods) is crucial. Requiring a minimum password length of 15 characters along with two upper, two lower, two number, and two special characters should be considered a minimum-security standard (in our opinion). Note that literature claiming that “passwords are dead” or “don’t use complex passwords” are referring to human users and their daily workforce access systems. Our guidance regarding minimum password strength refers to use cases such as privileged credentials on federated and non-federated systems like servers, databases, mainframes, and so on

*   Password/Secret vaulting: Password (or secret/key) vaulting is the process of storing the string used for authentication within a secure repository that provides encryption, non-repudiation, and access control. Vaulting passwords (or other forms of secrets) is a key security control which serves as a backbone for other security controls. Without first storing the value in a secure repository, you cannot enforce other controls. This helps prevent credentials from being stolen by the Vault’s access control mechanisms, and subsequently by enabling other controls such as rotation and isolation.

*   Password/Secret rotation: Password (or secret/key) rotation is the process of automatically changing the password value based on a defined security policy or potentially triggering the change to begin manually while still having the rotation process itself performed via automation. This is used in conjunction with complex passwords/secrets to automatically shorten a password’s time-to-live and is helpful in killing any credential residue that may have been left behind via hashes or logs, which are often target locations for credential theft.

*   Credential and session isolation: Credential and session isolation is the mechanism that ensures the credential (for example, password, secret, key, and so on) and the session (for example, RDP, SSH, web, and so on) is isolated from the end-user’s workstation and the end-user themselves. End-users and workstations are the weakest links within most organizations, making them the point of entry for most malicious actors. Therefore, you want to ensure that you’re keeping both the credential and the endpoint you’re connecting to out of harm’s way using bastion hosts that automatically establish sessions to the target resource without the user needing to know the password.

*   Removal of hard-coded credentials: Removal of hard-coded credentials is the process whereby developers replace the hard-coded credentials that exist inside their code, whether through .ini files, embedded user/pass values, environment variables, and so on. They replace them with an authenticated and secured process through which the code can be provided for that credential/secret safely and on-demand. Application code and CI/CD pipeline tools are common targets for malicious actors to steal credentials from, so by removing the static passwords from those applications, you reduce the risk of those credentials being stolen.

*   Credential store protection: Credential store protection is a mechanism that secures known credential stores, such as the Windows LSASS process or Google Chrome Password Store, from unauthorized access. Those credential stores often contain an end-user’s passwords to various systems or web applications. Malware will often attempt to access these known stores to steal credentials, so protecting these credential stores will naturally result in a reduction in credential theft.

*   Keystroke logging protection: Keystroke logging protection is an important mechanism to prevent malicious actors from scraping the input of an end-user’s keyboard digitally, a technique commonly used to steal credentials at the time of login. You can implement keystroke logging protection in a few ways. The first is through preventing malicious code, such as a keystroke logger, from executing on the end-user’s workstation using application control. Secondly, you can protect against credential theft from keystroke loggers by isolating the credential and the session using the same bastion host technique described in credential and session isolation. If the system never has access to the password and the user never has to type it in, there’s nothing to steal.

Stop lateral and vertical movement
------------------------------------------------

*   Role-based access control: RBAC is a permissioning technique to grant identities access to resources in a least privilege model, based solely on the role’s required function or duties. This helps prevent lateral and vertical movement by limiting the role’s scope of access to only the resources and permissions required for that role.

*   Just-in-time access: Just-in-time (JIT) access is an access provisioning technique where identities do not have freestanding access to resources and are only provided this access at the exact time that it’s needed. This reduces the potential for access to be compromised and used to traverse a network, as the identity is only given its access by the security control plane at the time when the authorized identity needs it.

*   Randomized/unique local credentials: This is the technique of applying randomized password values, and ideally unique values, on every local endpoint or system. This approach to password management ensures that local account passwords cannot be reused from system to system, a practice that would otherwise leave organizations vulnerable. By having each of those endpoint credentials be unique and random, a malicious actor who has managed to compromise a single system through a local account cannot get lucky and compromise other systems because they do not share the same local account passwords, thus reducing the risk of lateral and vertical movement to other systems.

*   Limit scope of influence (blast radius): This is an approach to permissioning and granting access to systems/resources whereby you attempt to limit the number of systems a federated identity has access to (similar to role-based access control, but not necessarily based on roles). This could include techniques like credential boundaries for tiered systems. The result of this is reducing the “blast radius” of the identity should it ever become compromised, reducing the risk of lateral and vertical movement to other systems.

*   Session isolation: Session isolation is the mechanism that ensures the session (for example, RDP, SSH, web, and so on) the end-user establishes to a target resource is isolated from the end-user’s workstation. It also ensures that an end-user is accessing only the specific resource they needed, which helps prevent the user from moving laterally or vertically should they choose to perform some malicious action.

*   Session protection: Session protection is a mechanism that protects the client-side of web browser-based sessions by blocking file downloads from the web app, access to clipboard or drag and drop, or access to the right-click context menu, and can protect the Chrome process from being manipulated or abused by unauthorized applications. Protecting the session from hijacking helps prevent malicious actors from leveraging that access to move laterally or vertically to other resources.

*   Session analytics: Session analytics is a mechanism through which audit logs and session activity are automatically analyzed to determine whether the end-user is performing any unauthorized or malicious actions, and if so, alerting on these actions. Examples of potential malicious actions include session escapes, unauthorized new user creations, or attempting to move laterally or vertically throughout the environment.

*   Environment analytics: Environment analytics is a mechanism that looks at logs from various endpoints and sources for signs of compromise, suspicious behavior, or malicious actions, which could include attempts to circumvent security controls to move laterally or vertically. Any activities that might indicate a security event will then trigger an appropriate alert.

*   Adaptive response: Adaptive response is a mechanism that enhances both session and environment analytic capabilities with the ability to automatically respond to instances of suspicious or malicious behavior. For example, an automated response might come in the form of terminating a session in progress or automatically onboarding a privileged credential that was created out-of-band. This automated remediation helps prevent lateral and vertical movement by quickly killing the path through which a malicious actor would try to move laterally or vertically.

*   Application control: Application control is a mechanism whereby the security policy defines settings such as which applications can or cannot be launched, which users can launch them, whether those apps will run with elevated permissions, when the app can be launched throughout the day/week, and more. This helps contribute to a reduction in lateral and vertical movement by preventing malicious processes or applications from accessing known credential stores, which is a common technique used to steal credentials.

Limit privilege escalation and abuse
--------------------------------------------------

*   Audit logging: Audit logging is a mechanism whereby auditable records are created for various human and non-human user activities. These audit logs are the cornerstone to enabling other security controls. After all, if you don’t know what’s happening or has happened, how can you respond to it? This helps reduce the risk of privilege escalation and abuse by creating a non-repudiated trail of activity that you can review in real time or post-session for signs of escalation and abuse attempts.

*   Privilege analysis: Privilege analysis is the process whereby the privileges of an identity or account are analyzed, assessed for risk, and determined to be valid, or not, for that entity. This is an extremely helpful step in implementing a least privilege model, which should help mitigate the risk of permissions being abused or inappropriately escalated.

*   Least privilege enforcement: Least privilege enforcement is the mechanism whereby an identity’s privileges are proactively reduced to the minimal level required to perform their function or role. This helps mitigate the risk of permissions being abused or inappropriately escalated.

*   Session recording: Session recording is the mechanism whereby a human-interactive session with a target resource or system (for example, Windows or *NIX server, website, and so on) is text and/or video recorded. This is a helpful reactive forensic tool to understand privilege escalation and abuse during sessions, but also acts as a deterrent control.

*   Session analytics: Session analytics is a mechanism through which audit logs and session activity are automatically analyzed to determine whether the end-user is performing any unauthorized or malicious actions, and if so, alerting on those actions. Examples of potential malicious actions include session escapes, unauthorized new user creations, or attempting to move laterally or vertically throughout the environment.

*   Environment analytics: Environment analytics is a mechanism that looks at logs from various endpoints and sources for signs of compromise, suspicious behavior, or malicious actions, which could include attempts to abuse or inappropriately escalate permissions. Any activities that might indicate a security event will then trigger an appropriate alert.

*   Adaptive response: Adaptive response is a mechanism that enhances both session and environment analytic capabilities with the ability to automatically respond to instances of suspicious or malicious behavior. For example, an automated response might come in the form of terminating a session in progress or automatically onboarding a privileged credential that was created out-of-band. This automated remediation helps prevent privilege escalation and abuse by terminating a session wherein unauthorized or abusive actions were identified.

*   Continuous authentication: Continuous authentication is a mechanism where end-users are prompted to re-authenticate their session through a defined set of authentication factors under certain conditions. Through the use of these authentication factors, you can help ensure that only the user with the same identity as the one that originally initiated the session is able to resume the session. This helps prevent privilege abuse by ensuring that idle user sessions cannot be compromised by a malicious actor lurking on the machine, attempting to impersonate the user.

*   Lifecycle management: While lifecycle management (LCM) is typically thought of as a process rather than a security control, in practicality it still is a security control. The mechanism of approving permissions and privileges, granting them to users, and periodically re-certifying and/or revoking those privileges when appropriate actually helps reduce the risk of privilege escalation and abuse by reducing the likelihood that a user will continue to carry permissions they no longer require, which is a commonly abused scenario by malicious actors.

*   Application control: Application control is a mechanism whereby the security policy defines settings such as which applications can or cannot be launched, which users can launch them, whether those apps will run with elevated permissions, when the app can be launched throughout the day/week, and more. This helps to prevent malicious software from running, regardless of the level of privilege being leveraged.
